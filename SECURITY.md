# Security Policy

## Supported code

TrainerForge is under active development. Security fixes target the current
default branch (`main`). Historical development snapshots do not have a separate
security maintenance commitment. Review a reported issue against the relevant
development branch when it has not yet reached `main`.

## Reporting a vulnerability

Report vulnerabilities only through
[GitHub private vulnerability reporting](https://github.com/NaXeMate/Trainer-Forge/security/advisories/new).
This channel must be enabled in the repository settings before reports can be
submitted. If the form is unavailable, do not disclose vulnerability details in
public issues, pull requests, or discussions. No alternative reporting channel
is currently designated.

Include the affected branch or commit, steps to reproduce the issue, its impact,
and a proof of concept using synthetic data. Do not include real credentials,
tokens, or personal data. Do not open a public issue containing exploit details.

## Response and remediation

Reports are reviewed according to their severity and maintainer availability.
No fixed acknowledgement, response, or remediation deadlines are promised.
Follow-up communication takes place in the private GitHub report.
